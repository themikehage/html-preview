# html-preview

> Self-hosted server that turns an HTML page or a static folder into a stable preview URL in under a second. Built for AI agents: deploy, get the URL, share it.

Base URL: http://localhost:3000
OpenAPI: http://localhost:3000/openapi.json
MCP (streamable HTTP, POST only): http://localhost:3000/mcp
Content is served from a separate origin and is sandboxed: no cookies, no storage, relative asset URLs only.

## Authentication

Every /v1 and /mcp request needs `Authorization: Bearer <api key>` (keys start with hp_). Scopes: read (GET), deploy (create/change/delete previews), admin (keys, usage). admin implies all.

## Common flows

1. Single page (80% of cases)
   curl -X PUT -H "Authorization: Bearer $KEY" -H "Content-Type: text/html" --data-binary @index.html "http://localhost:3000/v1/previews/my-page?ttl=24"
   The response starts with "url": open or share it. Re-deploying the same name updates the preview.

2. Folder (build output)
   zip -r site.zip dist && curl -X PUT -H "Authorization: Bearer $KEY" -H "Content-Type: application/zip" --data-binary @site.zip http://localhost:3000/v1/previews/my-site
   A single top-level folder is stripped. Use relative asset URLs (Vite: base './'); read "warnings" in the response.

3. Large or incremental deploys (manifest)
   POST /v1/previews/{name}/deployments with {"files": {"index.html": {"hash": "<sha256>", "size": 123}}} -> {"deploymentId", "missing": [hashes]}
   PUT /v1/blobs/{sha256} for each missing hash, then POST /v1/previews/{name}/deployments/{id}/finalize.

Roll back with POST /v1/previews/{name}/rollback; delete with DELETE /v1/previews/{name}.

## Endpoints

- GET /v1/previews [read]: List previews
- GET /v1/previews/{name} [read]: Preview detail with its deployments
- PUT /v1/previews/{name} [deploy]: One-shot deploy: send an HTML page, zip, tar.gz or multipart files
- PATCH /v1/previews/{name} [deploy]: Change visibility, ttl, pinned or rename
- DELETE /v1/previews/{name} [deploy]: Delete a preview and its deployments
- POST /v1/previews/{name}/rollback [deploy]: Point the preview at an earlier deployment
- POST /v1/previews/{name}/deployments [deploy]: Manifest step: declare files by sha256 and get the blobs still missing
- POST /v1/previews/{name}/deployments/{id}/finalize [deploy]: Verify blobs and promote the deployment atomically
- GET /v1/previews/{name}/files [read]: Manifest of a deployment
- GET /v1/previews/{name}/files/{path} [read]: Read one file (served as text/plain or octet-stream)
- GET /v1/previews/{name}/links [read]: Share links of a private preview (no secrets)
- POST /v1/previews/{name}/links [deploy]: Create a share link for a private preview (URL shown once)
- DELETE /v1/previews/{name}/links/{id} [deploy]: Revoke a share link; it stops working immediately
- PUT /v1/blobs/{sha256} [deploy]: Upload a blob by content hash
- POST /v1/keys [admin]: Create an API key (token shown once)
- GET /v1/keys [admin]: List API keys (no secrets)
- DELETE /v1/keys/{id} [admin]: Revoke an API key
- GET /v1/usage [admin]: Totals, per-key usage and quota headroom
- POST /v1/admin/backup [admin]: Snapshot the database under DATA_DIR/backups (VACUUM INTO)

## MCP tools

deploy_html, deploy_files, list_previews, get_preview, update_preview, rollback_preview, delete_preview, share_preview, revoke_share

## Errors

Errors are JSON: {"error": {"code", "message", "fix"}}. Follow "fix". Codes: ALREADY_CURRENT, BAD_REQUEST, BLOBS_MISSING, CONFLICT, DEPLOYMENT_ALREADY_FINAL, DEPLOYMENT_NOT_FOUND, DEPLOY_TOO_LARGE, ENTRY_MISSING, FILE_NOT_FOUND, FORBIDDEN, HASH_MISMATCH, INSTANCE_FULL, INLINE_TOO_LARGE, INSUFFICIENT_SCOPE, INTERNAL_ERROR, INVALID_ACTOR, INVALID_ARCHIVE, INVALID_CREDENTIALS, INVALID_CSRF, INVALID_HASH, INVALID_MANIFEST, INVALID_MESSAGE, INVALID_NAME, INVALID_PATH, INVALID_REQUEST, KEY_NOT_FOUND, LAST_ADMIN_KEY, LINK_NOT_FOUND, METHOD_NOT_ALLOWED, NAME_TAKEN, NOT_FOUND, NO_DEPLOYMENT, NO_PREVIOUS_DEPLOYMENT, PAYLOAD_TOO_LARGE, PREVIEW_NOT_FOUND, PREVIEW_NOT_PRIVATE, RATE_LIMITED, TOO_MANY_FILES, TOO_MANY_LINKS, UNAUTHORIZED, UNKNOWN_HOST, UNSUPPORTED_MEDIA_TYPE, VISIBILITY_NOT_ALLOWED.

## Deploy warnings

Deploy responses include "warnings": ROOT_RELATIVE_URL, NO_ENTRY_HTML, LOCALHOST_URL, MIXED_CONTENT, LARGE_FILE, each with the offending "file" and a "fix".
